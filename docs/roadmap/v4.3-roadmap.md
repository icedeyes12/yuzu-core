# Yuzu Companion v4.3 — Architecture Roadmap

Status: Living roadmap. This document describes future outcomes and constraints; current runtime contracts belong in active architecture references and feature specifications.

## Vision

Transform Yuzu Companion from a single-host AI companion into a distributed AI platform with isolated execution environments.

## Core principles

1. AI never executes directly on the orchestration host.
2. Every user owns an isolated workspace.
3. Terminal execution is separated from Yuzu Core.
4. Yuzu Core orchestrates and applies policy; it does not perform privileged work.
5. Sandboxes are disposable, reproducible, independently resettable, and auditable.

## v4.3 outcomes

- A sandbox manager can select an available node and create a user-owned sandbox lazily.
- The node daemon exposes one authenticated execution contract over the phase-appropriate transport.
- Workspace paths, PTY identifiers, and sandbox identifiers are authorized and confined.
- Bootstrap artifacts are pinned and verified before installation.
- Backend-specific isolation guarantees are explicit; unsupported trust levels fail closed.
- A sandbox failure cannot take down Yuzu Core.

## Delivery milestones

### Milestone 1 — Transport and contract

Implement the canonical argv, shell, environment, working-directory, timeout, and result model. Keep SSH/CLI as the first transport because it is easier to debug; add HTTP/WebSocket only after the contract and authorization tests are stable.

### Milestone 2 — Node lifecycle

Add authenticated node registration, heartbeat, capability reporting, lazy sandbox creation, reset, destroy, and status transitions. Node selection must account for availability and declared isolation capabilities.

### Milestone 3 — Secure execution

Move terminal, Python, git, file editing, package installation, project generation, and code execution behind the sandbox manager. Apply policy before dispatch, enforce resource limits, and keep Yuzu Core responsible for authentication, memory, chat, embeddings, PostgreSQL, scheduling, and notifications.

### Milestone 4 — Workspace and terminal UX

Make the workspace the primary product concept: Chat, Files, Terminal, Projects, and AI. Interactive PTY sessions must reconnect safely, preserve authorization, and never expose host paths.

## Architecture boundary

The target flow is:

```text
User -> LLM -> Policy -> Sandbox Manager -> authenticated node daemon -> sandbox
```

The active node-daemon contract is maintained in [`../specs/yuzu-sandboxd.md`](../specs/yuzu-sandboxd.md). Current application ownership boundaries are maintained in [`../architecture/`](../architecture/).

## Open decisions

- Select the minimum isolation backend for each trust level and workload class.
- Define the node credential lifecycle, rotation, revocation, and audit retention.
- Decide which workloads may use PRoot and which require a stronger kernel boundary.
- Define resource quotas and cancellation behavior across SSH, HTTP, and WebSocket transports.
